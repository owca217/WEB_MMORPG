# Compact inventory and drag storage

Inventory slots are half their previous width and height: eight compact columns replace four within the existing panel. Quality borders and bottom-right stack counts remain. Details retain metadata and equipment actions; explicit move controls are removed.

Dragging a stored or pending item over an equipped container in the HUD immediately requests one complete-instance transfer, without waiting for release. Use the existing authorized move API and validate the current inventory, target capacity, source ownership, nonempty-bag restrictions and same-container exclusion. Invalid targets keep the item where it is. Show a following item icon and target feedback; block accidental game clicks and duplicate requests through release and asynchronous updates.

Mouse movement starts a drag after a small threshold. Touch uses a short hold before dragging so ordinary inventory scrolling remains available. Space picks up a focused item and Enter on an equipped HUD container provides keyboard access. Escape, cancellation, hiding, session changes and destruction clean up listeners, timers and visuals. Source and HUD communicate through existing item-instance attributes and a validated `data-container-drop-target` attribute.

Client worker owns pointer/keyboard interaction and the contents panel; root owns HUD targets, integration fixtures and native QA; Android worker prepares 0.1.21/code22. Local checks focus on changed drag behavior, affected panel/HUD/integration tests, TypeScript/build, and desktop/phone visual checks. Normal required CI and exact web/APK release verification remain in place. No backend API or schema changes.

Verification: controller and panel focused tests passed 17 cases; HUD tests passed 7; the existing WorldScene integration tests passed 13 after adapting move triggers to Space/Enter. Final client TypeScript and Vite build passed. Read-only review found cancellation losing a held-pointer release and compatibility mouseup reaching Phaser after source replacement; both were fixed with matching release capture and compatibility release shielding, with focused regression coverage.

Native browser QA measured 57.25×57.25 slots versus the previous 115.5×115.5 at the same desktop viewport. A real mouse drag moved a potion from the second bag into the permanent backpack; dragging onto its current bag left the item in place and did not open the chooser. Keyboard pickup and Enter moved a bow into the backpack. At 844×390, a mouse drag in the phone layout moved a potion into the second bag, and the details retained equip actions with no move controls. Touch long-press/pan behavior was covered by controller tests, not a physical Android device. The temporary viewport was reset and browser tab closed.
